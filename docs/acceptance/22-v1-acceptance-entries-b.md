## 1. D1 · 通知端到端断言到真收端，不是留痕表

片④ S1 判据原文是「通知端到端可达」。无真实 SMTP / IM 出口时，三个候选深度：

| 候选 | 断到哪 | 结论 |
|---|---|---|
| 只断投递记录与三次退避终态 | 平台内部账本 | **否决** |
| 只起 Webhook 回环，邮件只断留痕 | 半边 | **否决** |
| **compose 内起本地 SMTP sink + Webhook 回环接收端** | 真实网络投递 | **采纳** |

**决定**：`make acceptance` 的 compose 增起两个进程外的真实网络对端 —— 一个本地 SMTP sink、一个 Webhook 回环接收端；`AC-04-S1` 断言邮件真落到 sink、Webhook 真收到载荷与 HMAC 签名头。

否决第一档的理由是它正是 20 号 D4 要根除的形态：**出口一断就绿**，绿灯只证明平台自己记了账。否决第二档是它让唯一的原生渠道（SMTP，`02` §3.7 钉死的两渠道之一）逃掉，而 SMTP 恰是「不依赖任何外部系统就具备独立告警能力」这条产品承诺的落点。

**收端不是 mock，必须显式记账**：它是被测系统**之外**的真实 SMTP / HTTP 服务端，不是被测代码的替身，与 A 组「真 Agent 走真实接入」同构；根 `CLAUDE.md`「不造 mock」与 `05` §5 的接缝白名单都不适用于它。片④ spec 的快层用 `httptest` 与进程内 SMTP 收件端，那是快层的形态；矩阵这一层要的是**跨进程真网络**，两者不互相替代。

## 2. D2 · B 组两条 `F2` 记 `n-a`，各补回一条加深基线

沿 21 号 D6 对片⑨的处理法。

- **`AC-03-F2` → `n-a`**：处置、快照与性能事件都不是指标序列面，不产出封闭 13 码；告警历史筛选超出 90 天保留界是**自然空集**，片③ Further Notes 已明确不新增 `Unavailability` 码（承 `07` D7.e 对 30 天样本边界的处理）。
- **`AC-04-F2` → `n-a`**：通知域根本不是指标序列端点，渠道 / 联系人 / 策略 / 窗口的空集与未配置态都不映射 13 码。
- **`AC-02-F2` 不 `n-a`**：片②有真 13 码面 —— 规则列表的「所需能力是否满足」与告警详情**原样透传**片①产出的原因码。这条要守住「不造第二来源」。

补回的两条均 `baseline: true`：

- `AC-03-F5`：快照三态（成功 / 失败带原因 / 该类型不适用）严格可区分 —— 「不适用」绝不冒充「失败」、「失败」绝不冒充「空白」，三态一律以带结果的值返回不用 404。这是 `02` §3.10 最容易被实现成 404 的一处。
- `AC-04-F5`：渠道未配置是「未设置」不是 error，**且绝不静默** —— 无可用出口时留痕表必须出现一条带原因的失败记录，让用户能回答「这条告警为什么没通知到我」。

`n-a` 让出多少保护，补回多少。否决「硬凑 13 码条目」：把 `n-a` 的正当用法浪费掉，再造一条假条目。

## 3. D3 · `F3` 在片④读作「外部依赖不可用」

`F3` 的字面是「目标库不可达 / 能力不足」，但**通知域的外部依赖是出口，不是被监控库** —— 目标库不可达对通知没有任何直接语义。

**决定**：`AC-04-F3` 把 `F3` 读作「外部依赖不可用」，落成「真停 SMTP sink / Webhook 收端固定返 5xx → 固定 3 次指数退避 → 终态失败 + 失败摘要 + 导航角标」。

理由：`F3` 的本意（20 号 D2 表）是「外部依赖不可用时降级并给出原因，不表现为有数据但全零」，语义在通知域完整成立；且 S1 判据「失败三次退避留终态」由此天然有归宿，不必再造第三条 `n-a` + 补回。**这是一处语义映射，显式写在这里而不是默默扩义。**

同理记账：片②的 `F3` 由 **`NO_DATA` 路径**承载（停目标库容器 → FIRING 转 `NO_DATA`），能力不足面已在片① `AC-01-F3/F5/F6` 三条覆盖，片②不重复；片③的 `F3` 是快照采集失败。

## 4. D4 · 四条 `F4` 不复用手段，各断各的下游语义

「断平台库 → server 降级」这一手段，A 组已用在 `AC-01-F4` 与 `AC-09-F4`。B 组三片各来一次即同一手段跑五次，看着像重复。**决定：手段同源，断言点完全不同，三次执行都保留。**

| 条目 | 断什么 |
|---|---|
| `AC-02-F4` | 平台库不可达期间**不得**把目标实例判成 `NO_DATA`、不得产生告警实例；恢复后不回放不补评估 |
| `AC-03-F4` | 平台自身故障**不得**写出半截处置事件、不得把既有快照改写为「失败」（证据面不被污染） |
| `AC-04-F4` | 平台自身故障**不得**发出通知，也**不得丢失**已排队的待发通知与退避进度 |

第三条尤其点名：它是片④「**待发通知落表而非内存队列**」那条本片决策的唯一验收面 —— 换成内存队列，这一条必红。

## 5. D5 · 维护窗口条目与横切 `INV-1` 的界

`AC-04-S2`（`baseline: true`）断「维护窗口这一种压制来源」的端到端事实：窗口内触发 → **收端零投递** + 告警实例与事件照常生成并带窗口标记 + `MAINTENANCE_SUPPRESSED` 事件 + 窗口结束不补发、由下一个 `repeat_interval` 自然接管 + 提前结束立即解除压制。

`INV-1`（「告警状态五档，压制是正交轴」，归 [#121](https://github.com/liumingjian/dbs-monitor/issues/121)）断的是**压制不改变五状态**这一不变式本身。按 20 号 D5，片④条目引用 `INV-1` 但**不计入**横切组达标 —— 横切独立计分，任一片全绿都不构成横切条目的覆盖。

## 6. D6 · 「凭据永不回显」并入 `AC-04-S1`，不单设条目

SMTP 密码与 Webhook 密钥是 ADR-09 的唯一例外条款，片④是它们的**唯一产地**。

**决定**：API 面的断言（**响应中不存在秘密字段**，非「返回掩码字符串」；B7 禁名单扫描）并入 `AC-04-S1` 的同一次执行；UI 面的断言（呈现为「已设置 / 未设置」）并入 `AC-04-S3`。不单设条目 —— 单设会造出一次只为扫字段的独立执行。

## 7. D7 · 三处参数化，两处坚决不参数化

### 7.1 B 组时间参数化增补表（A 组 21 号 D7 已定的不重复）

| 参数 | 产品默认 | 验收值 | 说明 |
|---|---|---|---|
| 规则 `evaluation_interval` | 随规则 | **5s** | 与 A 组任务周期同频错相位 |
| `consecutive_count` | 规则可配 | **2** | 最小可证「持续判定不是单次抖动」 |
| `NO_DATA` 门槛 | 固定 2 周期 | **不参数化** | 平台固定不可配，参数化即破坏语义 |
| `repeat_interval` **下限** | 15min（用户面校验） | **30s**（部署期配置项） | 见 7.2 |
| 快照会话上限 | 100 | **5** | 见 7.3 |
| 告警历史保留期 | 90 天 | **2min** | `AC-03-F6` |
| 通知退避次数 / 封顶 | 3 次固定 / 60s | **3 次不动 / 封顶沿用 A 组 5s** | 次数是语义，不参数化 |

B 组自身最长的一根是保留期的 2 分钟；加上 A 组分区滚动的 ~5 分钟长杆，**单轮 `make acceptance` ≤10 分钟仍成立**。

### 7.2 `repeat_interval` 下限做成部署期配置项（外溢到实现的硬要求之一）

spec 冻结「`repeat_interval` 必填、范围 15 分钟–24 小时、不可关闭」，与 ≤10 分钟预算硬冲突。否决两条：放宽用户面校验下限（改冻结语义）；不验收重复通知的真实时间轴（S1 判据「没人处理就一直吵」直接落空）。

**决定**：新增一个**部署期配置项**承载 repeat 下限（默认 15min，不进用户面 UI），用户面校验读该配置。验收调至 30s。与 21 号 D9「调低磁盘水位阈值算真实手段」同一口径 —— 走生产同一判定代码路径、无 mock、不改用户面语义。

### 7.3 快照截断上限做成配置项（外溢到实现的硬要求之二）

截断契约的实质是「优先保留直接命中对象与完整阻塞链 + 原始匹配数 + 截断标识」，这在 5 与 100 下**同样可判定**。为一条断言在验收环境拉 100 条连接与真锁链，性价比极差且不稳定；只留快层则违背 20 号 D5 的取向（S1 判据只有单测 = 未覆盖）。**决定**：上限参数化，验收调至 5，真造 8 会话 + 一条三层递归阻塞链。

### 7.4 两处坚决不参数化

`NO_DATA` 门槛（固定连续 2 周期）与通知退避次数（固定 3 次）是「平台固定不可配」的**语义本身**。一旦做成配置项，验收验的就不是产品了。这与 `repeat_interval` 下限不同 —— 那个本来就是配置面的边界值。

## 9. D9 · 浏览器两条，IA §6.4 由 `AC-03-S3` 一条承载

## 11. D11 · `exceptions` 仍为 `[]`，四样新东西都不登记

本组引入四样新东西，逐条定性：

| 新东西 | 定性 | 是否进 D4 白名单 |
|---|---|---|
| SMTP sink / Webhook 回环收端 | 被测系统之外的真实网络对端（同 A 组真 Agent） | 否 |
| repeat 下限调至 30s | 部署期配置项，走生产同一判定代码路径 | 否 |
| 快照截断上限调至 5 | 同上 | 否 |
| 告警历史保留期调至 2min | 同上 | 否 |

D4 白名单管的是「**绕过业务 API 的数据准备**」，四样没有一样在写业务表。

**一处需要显式记账的边界**：片③要在**目标库**上开真事务造锁等待与长事务。那不是平台业务表，不属 B11 禁令射程；写在这里，免得日后守卫误报时没人知道当初是怎么想的。
