## 1. D1 · IA §6.1 / §6.2 / §6.3 各挂一条浏览器条目

五条关键路径此前已定两条归属：§6.5 由 `AC-01-F2` 承载（21 号 D3），§6.4 由 `AC-03-S3` 承载（22 号 D9）。**剩下三条全部落在片⑤**——它们的起点与终点页面无一例外在观察面页面树内。

| 路径 | 承载条目 | 中段独有的断言点 |
|---|---|---|
| §6.1 日常巡检 | `AC-05-S1` | 实例列表三层信息契约；Agent 状态 / 最近采集时间 / 数据新鲜度是**独立列不参与健康**；总览置顶复用同一模型，列表与总览永不打架 |
| §6.2 CPU 或连接数异常排障 | `AC-05-S2`✦ | **跳转自动定位触发时间**、**跳会话与阻塞继承时间范围**（`03` §5.1/§5.2 全表继承），会话详情只给 PID 等原生线索且带时效提示 |
| §6.3 锁等待与阻塞排障 | `AC-05-S3`✦ | 锁等待列表 → 阻塞链 → **阻塞源**会话详情，首版只读（无 kill / cancel / 批量终止入口） |

**跳转的起点由 `AC-05-S2` 承担、终点断言不外借**：§6.2 的起点是「告警通知 / 总览异常卡片」，本条从**总览异常卡片**进——告警通知面归片④（`AC-04-S1` 真投递），不在浏览器条目里重跑一次通知。

## 2. D2 · 「13 码后端真实驱动」拆两条：`F2` 管广度，`F5` 管文案

片⑤ S1 判据原文「13 码空状态由后端真实驱动」，与 A 组 `AC-01-F2`（B6 四项 + §6.5 整条路径）**有真实重叠风险**：两者都在断 13 码。

**决定**：拆两条，按「码的广度」与「一个码的整条路径」切开。

| 条目 | 层 | 断什么 | 与 `AC-01-F2` 的界 |
|---|---|---|---|
| `AC-05-F2` | api | 片① 能产出的 **11 码逐码**由真实后端条件驱动出来，一律 200 + 码、不走 error 路径、不补 0 | `AC-01-F2` 只驱动一个码，本条驱动全部 11 个 |
| `AC-05-F5`✦ | browser | 11 码 × 观察面各页面：**每码有文案 + `03` §7.2 的去向链接**；`COLLECTION_PAUSED` 绝不渲染成「采集失败」或「数据库不可达」 | `AC-01-F2` 断 B6 四项与 §6.5 路径，本条断码的 UI 覆盖面 |

**范围按片⑤ spec 与 S1 跨片原则对账，写死在条目里**：本片真库驱动片①产出的 **11 码**；`COLLECTION_PAUSED` 的产生条件归片⑦（其 UI 断言已由 A 组 `AC-07-F2` 覆盖，本组只断「不冒充别的码」这一面）；`VERSION_UNSUPPORTED` 在 P0 无产生者，**13 码全表对账归片⑩**（[#110](https://github.com/liumingjian/dbs-monitor/issues/110)/[#114](https://github.com/liumingjian/dbs-monitor/issues/114)）。这三句必须留在矩阵行的 `reason` 里，否则日后会有人把「11 码」读成漏了两码。

`AC-05-F5` 升 `baseline: true`：它是 S1 判据原话的直接落点（21 号 D1 的规矩），且「空状态必须解释原因」是 `03` §1.4 的设计原则之一。

**否决 `AC-05-F2` 记 `n-a`**：13 码面在片⑤ 真实存在且是本片最核心的判据，靠 A 组一条与 vitest 守卫顶上去，等于让 S1 亲口拍板的判据在矩阵里没有归宿。

## 3. D3 · AntD 观感门：`AC-05-S4` 记 `n-a`，判定归 #115

`08` D2 的两处判据（50 行实例列表首次渲染、标准监控 22 图切换时间范围）是**人工观感**，没有可自动判定的阈值——把它写成 `covered` 就是 20 号 D6.5 明令禁止的伪装。

**决定**：设 `AC-05-S4`，`baseline: false`、`status: n-a`，`reason` 三句写全：

1. 不可自动判定——人工观感门，无机器阈值；
2. **人工判定归 [#115](https://github.com/liumingjian/dbs-monitor/issues/115)（真实 Linux 上的最终验收会话）执行**，结论回写骨架欠账第 4 条；
3. **实测卡顿即触发 `11` §9 二类（结构型）停下**：AntD 无预写替代方案，开 wayfinder 票交回 HITL，**不得自行换库**；ECharts 卡顿有预写后备（uPlot），走一类预授权路径。

**否决只写进本文不进矩阵**：不进 `matrix.yaml` 就不进 `acceptance-result.json`，也就不进 #114 的 Go/No-Go 报告——一道没人会在发版前想起来的门等于没有。`n-a` 与 `pending` 一样进报告的显式清单（20 号 D6.5），这正是它该待的地方。

**否决记 `pending`**：`pending` 的语义是「暂时测不了」，人工判定项属于「不可自动判定」，是 `n-a` 的正当用法，不是滥用。

## 4. D4 · 实例健康归并单设 `AC-05-S5`（api，加深基线）

归并全语义已经是 A5 强制测试登记表项（片⑤ Testing Decisions，alerting L1 纯函数表驱动，先红后绿）。**仍单设端到端条目。**

理由与 20 号 D5 对横切组的取向同源：**纯函数单测证明算得对，证明不了它真被接进了投影路径**。归并的入参跨四个片——已忽略标记读片③、已暂停事实读片⑦、维护中标记读片④、告警级别读片②——正是「接线错了单测全绿」的高危形态；而片⑤ 的本片决策把归并做成**服务端聚合读端点**，那条端点是唯一的口径出口，接错即全平台健康失真。

`AC-05-S5` 的断言点逐条对账归并全语义，全部由**真实告警事实**驱动（片②真规则触发 / 片③真忽略 / 片④真维护窗口 / 片⑦真暂停），无一条直插业务表：

- 判定顺序：已暂停 override → critical/warning 取最高 → 从未成功采集为未知 → 否则正常；
- 已忽略退出归并（不进主状态、不计 C/W/I、不进归因行，**但告警列表仍可见**）；
- info 不染色，纯 info 时归因行展示最早那条；
- 「未知」一次性单调：唯一入口是从未成功采集，首采成功后永不再回（此后失联由内置规则染色，不变灰）；
- 归因行取最坏级别中**首次触发最早者**，不堆叠多行；
- 绿色永不等于「什么都没有」：计数为 0 也不隐藏已忽略 / 配置缺失标记；
- 结构性不适用与配置缺失不产生告警、不进健康。

层选 `api`（20 号 D3：投影正确性在 UI 上没有独立语义，UI 只是同一份 JSON 的转述）；三层信息契约的**呈现**面留在 `AC-05-S1` 的浏览器执行里。`baseline: true`——它不是 S1 判据原话，但「页面树全部可用」的前提是投影不失真，且这条是本组唯一会让**全平台**读数错误的路径；按 21 号 D1，升基线的理由写在这里而不是默默升。

## 5. D5 · 片⑥ 的 `F3` / `F4` 切法，与背压—`NO_DATA` 张力的显式记账

片⑥ 有一处**表面矛盾**，必须写下来而不是靠实现者临场猜：

- [T14](../design/14-platform-observability-and-diagnostics.md) / 20 号 D2 的 `F4`：平台自身故障**不得计入 `NO_DATA`**；
- [`12`](../design/12-collection-concurrency-timeouts-and-backpressure.md) D7 明文：**背压跳过不推进采集源完整性水位，连续缺数照常进 `NO_DATA`**。

**决定：`12` D7 的口径优先，`AC-06-F4` 不断 `NO_DATA` 豁免，并把这句写进条目的 `reason`。**

两者不真矛盾：T14 管的是「平台**故障**」（平台库挂了、server 崩了——目标库根本没被观测），背压跳过是平台**按设计**主动放弃这一轮采集，观测义务确实没完成，用户确实缺了数，`NO_DATA` 报的是事实。掩盖它才是错的。

由此定 `F3` / `F4` 的切法：

| 条目 | 层 | 读作 | 断什么 |
|---|---|---|---|
| `AC-06-F3` | browser | 目标库侧：能力不足 / 不可达 | 逐图局部降级、**单图降级不累及他图**、能力四态可见、原因码属封闭 13 码；并入「调周期 5s→10s 后原始点距如实变 10s、响应回传粒度跟着变、**不谎称仍是 5 秒**」（见 D9） |
| `AC-06-F4` | browser | 平台侧：自我保护细因 | `SKIPPED_BACKPRESSURE` / `BACKOFF` 与目标库故障**在呈现上可区分**（`12` §5.3 的展示层兑现）；跳过绝不渲染成「数据库不可达」或「采集配置错误」；**显式不断 `NO_DATA` 豁免** |

**否决「背压归 `F3`、`F4` 改用断平台库」**：那会让片⑥ S1 判据「能力不足局部降级并显示原因」与「平台自我保护可区分」两件事挤进同一条 `F3`；且断平台库这一手段 A/B 组已跑五次（`AC-01/02/03/04/09-F4`），在**纯读取页**上第六次跑它，下游语义与 `AC-01-F4` 高度重合。

**否决再加一条 `F5` 分收**：`F3`/`F4` 的两个语义已各得其所，多一条只多一次浏览器执行。

## 6. D6 · 片⑥ `F1` 不记 `n-a`，落成「无写面」的验收

片⑥ 没有任何写操作面（本片决策原文：「本页无任何写操作面，全部读取为既有只读角色声明，不新增 `x-required-role` 条目」），照字面 `F1`「权限拒绝」似乎无对象。

**决定：不记 `n-a`。** 20 号 D2 的 `n-a` 准入是「该语义在本片不存在」，而片⑥ 的权限语义**存在且被产品明文承诺**——ADR-09「可见性不收窄」：页签对全部角色可见、不设开通与启用门槛（user story 2：最需要它的时刻没有门槛）。

`AC-06-F1`（api）断两件事：

1. 三档角色会话各打开增强页，**页签可见、数据一致、无任何降级或提示「需要更高权限」**；
2. 该页涉及的全部 `operationId` 在 OpenAPI 里**没有一条写语义的 `x-required-role`**——这是「本页无写面」这条本片决策的**唯一验收面**，一旦有人在增强页加了写端点，这条必红。

第 2 点是本条存在的真正理由：它守的不是权限，是**页面职责边界**。

## 7. D7 · 片⑤ 的 `F1` / `F4` 与 A/B 组同名条目的界

**`AC-05-F1`（api）**：观察面同样几乎无写入口（暂停归片⑦、处置归片③、规则归片②）。本条断的是「可见性不收窄」的**最大面**——三档角色在实例列表、总览、会话与阻塞、全局告警两列表所见的**实例集合与字段完全一致**，且观察面不出现任何可用的写入口。

与已有三处的界：`AC-01-F1` 断采集周期写端点的拒绝语义；`AC-07-S2` 的浏览器面断采集配置模块「置灰并说明所需角色、入口不隐藏」；`AC-03-F1` / `AC-04-F1` 断各自域的写拒绝。**本条是唯一一条断「读取面无收窄」的条目**，覆盖的页面数最多，不可由前三条推得。

**`AC-05-F4`（api）**：手段与 `AC-01-F4` / `AC-09-F4` 同源（真停平台 PG 容器），断的是**健康证据面不被污染**：

- 平台库不可达期间，实例列表**不得把实例翻绿**、不得擦掉未恢复告警、不得把已有健康改写成「正常」或「无数据」；
- 平台自身故障必须表现为**平台侧不可用**（`09` D6 的语义，UI 面已由 `AC-09-F4` 覆盖），而不是目标实例状态的变化；
- 恢复后归因行、C/W/I 计数、正交标记与故障前一致，**不回放、不重算出第二个结论**。

「绿色是最危险的谎」——这是观察面独有的下游语义，`AC-01-F4`（零样本零告警）与 `AC-09-F4`（不白屏不 502）都断不到。

## 8. D8 · 片⑤ `F3` = 会话与阻塞降级 + 查询统计排行五态

`F3`（目标库不可达 / 能力不足）在片⑤ 的天然归宿是**查询统计排行**——`03` §4.5 与片⑤ user story 14 已经把五态钉死：未启用 / 权限不足 / 暂时不可用 / 统计已重置 / 区间内无记录。

`AC-05-F3`（api）断：五态**严格可区分**、**绝不表现为空表或「暂无数据」**、页面只说明能力状态与排查方向（不提供启用扩展 / 提权按钮）；并断目标库不可达时会话与阻塞页降级、明示最近一次成功采集时间与新鲜度，**不把旧快照当实时**。

与 `AC-01-F3`（真回收 `pg_monitor` → `MISSING` + 影响 N 项指标）的界：那条断的是能力快照与指标序列的降级，本条断的是**会话面的五态投影**——`pg_stat_statements` 的「统计已重置」与「区间内无记录」两态在片① 完全没有对象。

## 9. D9 · C 组时间参数化增补（A/B 组已定的不重复）

| 参数 | 产品默认 | 验收值 | 说明 |
|---|---|---|---|
| 增强页时间窗口 | 30 分钟（默认档） | **不参数化，也不真等 30 分钟** | 30 分钟是**查询窗口下界**，不是等待时长：任务周期已按 A 组参数化为 5s，采 1 分钟即有 ~12 个原始点，窗口 `[now-30m, now]` 照常发、`step=raw` 照常回传实际粒度 |

## 13. 已接受的代价

1. **浏览器条目 7 条**，是 A 组（4 条）与 B 组（2 条）之和还多。片⑤⑥ 的断言点几乎全是「用户看到什么」，20 号 D3 的判据把它们全推上浏览器——这是片的性质，不是本组放纵。代价是 `make acceptance` 的浏览器段最长。
2. **`AC-05-S5` 的跨片准备最重**：要同时有真规则触发、真忽略、真维护窗口、真暂停。它对执行顺序有隐含要求（片②③④⑦ 的条目先跑，事实可复用），实现期若发现串不起来，回写 supersede 记录而不是改成直插表。
3. **「11 码」而非「13 码」**是本组的真实覆盖面，两码的缺口在矩阵里显式留给片⑩。读矩阵的人必须看 `reason` 才知道这不是漏。
4. **AntD 观感门是 `n-a`**，意味着 v1 可以在观感未判定的状态下通过自动门。对冲是它进 Go/No-Go 报告的 `n-a` 清单，且判定归属（#115）与触发后果（`11` §9 二类停下）都写死在条目里。
